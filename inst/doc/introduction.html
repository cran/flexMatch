The task

flexMatch helps construct matched event windows when units experience treatment at different times. It makes sample eligibility and matching visible before estimation. A clean window and good covariate balance do not establish causal identification: parallel trends, anticipation, repeated treatment and the target estimand still need substantive justification.

Example data

The treatment indicator marks event starts. k_pre and k_post define the window; k_freeze extends the cooldown after an event. Matching uses covariates at match_by = -1 by default, with exact matching on the event period. Period distances count the ordered periods present in the input. A completely missing calendar period must be handled in the input before using these distances.

Balance thresholds are descriptive aids. They do not prove parallel trends or eliminate unobserved confounding.

Choose controls and histories

Use control_type = "nevert" for never-treated controls or "nyt" for eventual adopters before their first event. "all" and "nt" currently select the same clean-window pool. treated_type = "all" allows repeated events that satisfy the window rules. This assumes earlier events have no remaining relevant effect after the chosen cooldown; that assumption should be justified.

include_all_years = TRUE retains observed histories and bins periods outside the window. Those extra observations are not guaranteed to satisfy the clean-window rules and should not be treated as automatically uncontaminated controls for estimation.

The wrapper uses matching weights, a unit-within-set fixed effect, a matched-set-by-calendar-period fixed effect, and clustering by the original unit. Pooled stacked estimates still require an appropriate weighting and treatment-effect interpretation; this wrapper does not implement every modern difference-in-differences estimator.
